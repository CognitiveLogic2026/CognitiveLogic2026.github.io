# Enterprise Delivery Framework Template

Status: Approved

This template defines the official documentation structure for every Delivery Framework document.

Each document shall:

- use consistent terminology;
- remain technology independent;
- support measurable governance;
- maintain decision traceability;
- integrate with the Enterprise Service Catalogue;
- comply with the QEN Sovereign Intelligence Architecture.

## Required Document Metadata

Every Delivery Framework document shall begin with the following metadata table:

| Field | Required Value |
|---|---|
| Document ID | Unique DF identifier |
| Document Name | Official framework title |
| Programme | Commercial Evolution 1.0 |
| Phase | Phase 5 — Enterprise Delivery Framework |
| Domain | Foundation, Execution, Evidence, Decision, Quality or Operations |
| Version | Controlled semantic version |
| Status | Draft, Approved, Superseded or Retired |
| Classification | Enterprise Internal unless otherwise authorized |
| Document Owner | Accountable governance function |
| Approval Authority | Authorized approval body |

## Mandatory Document Structure

Every Delivery Framework document shall contain, where applicable:

1. Purpose
2. Scope
3. Normative Alignment
4. Sovereign Intelligence Alignment
5. Principles
6. Governance
7. Process Description
8. Roles and Responsibilities
9. Inputs and Outputs
10. Quality Controls
11. Evidence Requirements
12. Measurement and KPI
13. Risk Considerations
14. Auditability
15. Traceability
16. Continuous Improvement
17. Conformance
18. Architectural Notes

## Cross-Framework Consistency

Every Delivery Framework document shall:

- avoid duplicating normative content already defined in other approved frameworks;
- reference related Delivery Framework documents where appropriate;
- preserve architectural consistency across all Phase 5 domains;
- maintain alignment with ADR-CLE-004 — QEN Sovereign Intelligence Principle;
- remain evidence-first, governance-first, measurement-first, explainable and auditable;
- preserve technology independence and provider independence.
